Rules & Skills: Teaching Your AI Assistant

Cursor 2.0 introduces two powerful ways to customize AI behavior: Rules provide persistent instructions, while Skills give agents specialized capabilities for specific tasks.

Understanding Rules

Rules are persistent instructions that guide how the AI agent works across all your conversations. They're like having a senior developer's preferences and coding standards automatically applied to every AI interaction.

Rules in Cursor come in three types:

  • Project Rules - Stored in `.cursor/rules/`, version-controlled with your code
  • User Rules - Global preferences that apply across all your projects
  • Team Rules - Organization-wide standards managed from the dashboard (Team/Enterprise plans)
Creating and Managing Rules

Setting up rules is straightforward:

Open Cursor Settings (Cmd+, or Ctrl+,), navigate to "Rules, Commands" section. Click "+ Add Rule" to create a new project rule.

Rules support different application modes:

  • Always Apply - Applied to every chat session automatically
  • Apply Intelligently - Agent decides when it's relevant based on description
  • Apply to Specific Files - Triggered when working with files matching a pattern
  • Apply Manually - Invoked explicitly using @rule-name in chat
Hands-On: Creating Your First Rule

Let's create a rule that enforces coding standards:

Create a new project rule in `.cursor/rules/` called coding-standards.md with the following content: --- description: "Enforce project coding standards and best practices" alwaysApply: true --- ## Coding Standards - Use TypeScript for all new files - Prefer functional components in React - Add JSDoc comments for all exported functions - Use async/await instead of .then() for promises - Keep functions under 50 lines

Once created, this rule will automatically guide the AI agent's code generation across your entire project.

Skills: Specialized Agent Capabilities

Skills are a newer feature (introduced in Cursor 2.4) that allow agents to discover and apply domain-specific workflows when relevant. Unlike always-on Rules, Skills are dynamic and procedural.

Skills are defined in `SKILL.md` files and can include:

  • Custom commands and scripts
  • Step-by-step procedures for common tasks
  • Domain-specific knowledge and workflows
  • Tool integrations and automation patterns

Agents can discover skills automatically or you can invoke them using the slash command menu.

Rules vs Skills: When to Use Each
Rules Skills
Declarative, always-on guidance Procedural, task-specific workflows
Coding standards, conventions Complex multi-step procedures
Applied automatically Discovered dynamically when needed
Keep under 500 lines Can be more extensive
Best Practices
  • Start with simple rules and add complexity only when needed
  • Provide concrete examples in your rules, not just abstract guidance
  • Version-control project rules with git so your team benefits
  • Use Skills for procedural "how-to" instructions
  • Reference existing files instead of copying code into rules
Don't over-optimize before understanding your patterns. Add rules when you notice the agent making the same mistake repeatedly.
